### 1.4 路由命名规则

| 规则 | 说明 | 例 |
| --- | --- | --- |
| 目录名 = 文件名 = 路由名，短横线小写 | 页面目录与四件套同名 | `invoice-apply/invoice-apply.{js,json,wxml,wxss}` |
| 主包 = 高频路径 | 点单主链路留在主包 | `pages/store-detail/store-detail` |
| 分包 = 个人中心类 | 统一放 `packageUser`，`app.json` 声明 `preloadRule` 预加载 | `/packageUser/pages/address/address` |
| 多词页面用 `父-子` | 归属清晰的子页面 | `invoice` / `invoice-apply` / `invoice-detail` / `invoice-title` |
| 跳转 API | tab 页用 `switchTab`，其余用 `navigateTo`（返回用 `navigateBack`） | `wx.switchTab({url:'/pages/orders/orders'})` |
| 查询参数 | 单参数直接拼，不加 `?` 前缀冗余 | `?orderId=LBZ20261015000001` |
| 数据回传 | 跨页回传走 `getApp().globalData.__xxx`（如 `__couponPicked`），不用 URL | — |

### 1.5 接口请求封装

统一走 `utils/request.js`，页面不感知 token / 重试 / 错误码：

```js
request({ url, method='GET', data, idempotent=false, noAuth=false, timeout })
```

| 能力 | 行为 |
| --- | --- |
| 鉴权 | 自动带 `Authorization: Bearer <token>`；`noAuth:true` 时跳过 |
| 401 | **静默重登录 + 原请求重放一次**（`__retried` 标记防死循环） |
| 幂等 | `idempotent:true` 的请求失败自动退避重试，并复用同一个 `Idempotency-Key` |
| 去重 | 同 URL+参数的并发请求合并在途 Promise |
| 错误 | 统一 `{code,message}`；`toastError(e, fallback)` 直接 toast 且不抛未捕获异常 |
| 上传 | `wx.uploadFile` → `config.BASE_URL + '/upload'`，`services/service.js` 内封装 |

| 变更 | 旧版 | 现在 | 原因 |

### 3.3 各功能页面结构要点

| 功能 | 页面结构（自上而下） |

| **加盟咨询** | 全屏红色渐变海报（品牌行 → 主标题 → 副标题 → 四宫格亮点 → 白色二维码卡：图片或纯 CSS 占位图 + 提示 + 企微号）→ 操作区（保存到相册 / 预览海报 / 拨打加盟热线）→ 离屏 `canvas 2d` |
| **协议及政策** | 列表卡片（图标 + 标题 + 版本徽标 + 摘要 2 行 + 更新时间 + `›`）→ 页脚版本说明 |
| **协议详情** | 头部（标题 + 版本 + 更新时间 + 摘要）→ `rich-text` 正文卡（服务端 HTML，字号 28rpx / 行高 1.85）→ 页脚 → 失败态带「重新加载」 |
| **个人资料** | 头像（`open-type="chooseAvatar"`，固定 132rpx 圆形）→ 昵称（`type="nickname"`）→ 性别分段（男/女/保密）→ 手机号（`getPhoneNumber` 绑定/更换）→ 生日 `picker mode="date"`（上限今天）→ 城市 `picker mode="region"` → `.action-bar` 保存（改动后才高亮） |
| **账号设置** | 账号卡（openid 尾号 / 注册时间 / 会员）→ 切换账号 → 退出登录 → 危险区：注销账号（二次确认，需手输「注销」） |
| **发票管理** | 吸顶两 Tab（待开票订单 / 开票历史）→ 抬头管理入口 → 订单卡（订单号/门店/时间/金额/件数/「申请开票」）或历史卡（抬头+状态胶囊+订单号+金额+时间+备注）→ 空态引导 |
| **申请开票** | 订单卡（订单号/门店/就餐方式/时间/明细/实付；被驳回过给红字提示）→ 抬头选择（单选列表 + 新增/管理）→ 接收邮箱 → 同意《开票须知》勾选 → `.action-bar` 提交 |
| **开票详情** | 状态头（PENDING 红 / ISSUED 绿 / REJECTED 灰）→ 三步时间线（提交申请 → 商家受理 → 发票开具）→ 发票信息 KV → 已开具的文件卡与按钮 / 已驳回的原因卡与重提 → 订单快照（含明细与实付） |
| **门店列表** | 定位状态条（OK / DENIED / LOADING / IDLE）→ 搜索框（带清除）→ **吸顶下拉筛选栏**（营业状态 / 门店类型 / 距离范围，面板挂在栏下沿，选中项高亮）→ 门店卡（名称+类型/营业/当前标签、地址、距离·营业时间·人均、导航/打电话/选择该店）→ 空态带「清除筛选」 |
| **门店详情** | 顶部 `map`（`markers` + `show-location`，右上悬浮「🧭 导航」）→ 压住地图下沿的门店主卡（名称/类型/营业状态/营业时间/距离/「当前下单门店」角标）→ 信息卡（地址/电话/营业时间/人均/桌位/加盟商）→ 底部栏（电话 / 导航 / 选为下单门店） |

## 六、实现要点与设计决策

| 决策 | 理由 |
| --- | --- |
| 客服用 **4s 增量轮询**（`since`）而不是 WebSocket | 小程序 WebSocket 需域名备案 + 长连接保活；餐饮客服消息量小，轮询便宜、可重试、可断点续传（`since=maxId`）。小程序切后台时 `onHide` 停止轮询 |
| 媒体用 **multipart** 而不是 base64 | base64 体积 +33%，且要整块拼字符串，低端机上传 10MB 视频会 OOM；`wx.uploadFile` 天然流式 |
| 上传 **扩展名白名单 + magic number 嗅探** | 只校验扩展名可被「改后缀绕过」；只校验内容会误杀无统一头的格式（AAC/OLE 文档），两者结合 |
| 一单一张发票（`UNIQUE uk_order`） | 与「开票须知」文案一致；驳回后可复用原行重提，保留时间线 |
| 抬头在申请时**快照** | 发票信息不能被追溯篡改 |
| 注销 **匿名化** 而不是物理删除 | 订单/审计数据需要保留（合规与对账），但个人身份信息必须清除；`openid_hash` 留痕便于客服追溯 |
| 地址默认唯一 + 删除自动补位 | 列表里永远有一个默认，下单/开票不会出现「无默认可选」 |
| 门店排序「由近到远」而非「营业优先」 | 见 5.6 说明 |
| `autoPickNearestStore()` 不覆盖手动选择 | 否则「特意选了朝阳店，重进又被改成东直门店」 |
| 加盟二维码未配置时用 **纯 CSS 占位图** | 运营忘传图时页面不能开天窗；海报合成也画出同款占位 |
| 协议正文 **不缓存** | 运营改完协议，用户下一次进入就应是新版本 |
| `.page` / `.tip` / `.empty__hint` 上提到 `app.wxss` | 13 个新页面共用一份定义，避免复制粘贴漂移 |

## 八、本次踩坑与修复记录

这次「功能已写完、但模拟器完全跑不起来」的排查过程，暴露了 4 个会反复咬人的坑，全部已修并沉淀进 `tools/README.md`。

### 8.1 `wx:elif` 被注释打断 → 整个项目编译失败（最隐蔽）

**现象**：模拟器空白，`getApp()` 返回 `null`、`getCurrentPages()` 长度为 0、`__wxAppData` 为空；IDE 日志里**没有任何编译错误**；`tools/audit-miniprogram.js` 还报「全部通过」。

**根因**：`pages/mine/mine.wxml` 里 `wx:if` 的 `</view>` 与 `wx:elif` 的 `<input>` 之间夹了一行注释，WXML 编译器报
`Bad attr wx:elif ... wx:if not found`，**整个项目编译失败** → 用户代码从未启动。

**定位手段**：`getApp() === null` + `__wxAppData` 空 + 路由栈空，是「编译失败」的指纹。用
`cli.bat preview --project <path> --qr-format terminal` 逼出真实错误（IDE 日志不记这个）。

**修复**：把 `wx:if/elif/else` 链拆成语义等价的三个独立 `wx:if`，彻底规避邻接约束。

### 8.2 `getElementByXpath` 匹配失败会返回「假元素」

**现象**：`eq('旧入口已移除', !!(await elOf(page, TXT('发票抬头'))), false)` 失败——明明页面上没有这个入口。

**根因**：Automator 的 `getElementByXpath` **在找不到匹配时不返回 `null`**，而是返回假元素对象：`text()` 恒为 `''`、`wxml()`/`attribute()` 抛错、`offset()` 恒为 `{0,0}`。连 `//*[contains(text(),"ZZZZ_NOT_EXIST")]` 都能「命中」。
**这意味着所有 `!!el` 形式的存在性断言都是假阳性，`tapXp` 也会对着空气点击。**

**修复**：真元素有 `tagName`，假元素 `tagName === undefined`，据此在 `elOf()` 里统一过滤。**修完后 [17]~[19] 段一批原本"通过"的断言才暴露出真实问题。**

### 8.3 `TXC` 与 `TXTIN` 用错（同名不同结构）

- 文案**直接写在元素上**（`<view class="panel__item">直营店</view>`）→ 必须用 `TXC`（class + 自身 `text()`）
- 文案**包在子 `<text>` 里**（`<view class="bar__item"><text>全部营业状态</text></view>`）→ 用 `TXTIN`

筛选面板 `panel__item` 与发票页 `tabs__item` 属前者，之前误用 `TXTIN` 导致点击落空、tab 切不过去。

### 8.4 测试不能依赖「自动匹配最近门店」的漂移

新增的「进入点单页自动匹配最近门店」会在用户从未选过门店时按定位挑店。模拟器定位漂到丰台店（该店有 2 个菜停售），断言 `totalDishes = 30` 就莫名变成 28。

**修复**：用例开头把定位钉在朝阳大悦城并清掉已有门店（`lbz_location_v1` + `lbz_store_v1`），让自动匹配**确定地**选中 `st_cy`；断言也改为与页面实际门店数据对齐（如加号数 = `d.totalDishes`）。
