## 一、必须由你提供的凭据（当前缺口）

| # | 项目 | 去哪儿拿 | 填到哪里 |
| --- | --- | --- | --- |
| 1 | **正式小程序 AppID** | 微信公众平台 → 开发管理 → 开发设置 | `lbz-chuanchuan/project.config.json` 的 `appid` |
| 2 | **小程序 AppSecret** | 同上（只显示一次，注意保存） | `server/.env` 的 `APP_SECRET` |
| 3 | **微信支付商户号 mchid** | 微信支付商户平台 → 账户中心 | `server/.env` 的 `MCH_ID` |
| 4 | **商户 API 证书序列号** | 商户平台 → API 安全 → API 证书 | `server/.env` 的 `MCH_SERIAL_NO` |
| 5 | **商户 API 私钥** `apiclient_key.pem` | 申请证书时下载 | 放到 `server/certs/`，路径填 `MCH_PRIVATE_KEY_PATH` |
| 6 | **APIv3 密钥**（32 位） | 商户平台 → API 安全 → APIv3 密钥 | `server/.env` 的 `APIV3_KEY` |
| 7 | **正式域名 + HTTPS 证书** | 自己的域名 + 备案 | `server/.env` 的 `BASE_URL` / `PAY_NOTIFY_URL` |

填完后改两个开关：

```dotenv
# server/.env
LOGIN_MODE=real
PAY_MODE=real
```

> 现在 `LOGIN_MODE=mock` / `PAY_MODE=mock`，所以整套系统**不需要任何凭据就能全链路跑通**
> （登录用派生 openid、支付用模拟收银台）。这也是交付包里测试能全绿的原因。

## 二、微信平台侧配置

### 2.1 小程序后台

| 项 | 位置 | 说明 |
| --- | --- | --- |
| 服务器域名 | 开发管理 → 开发设置 → 服务器域名 | `request` 合法域名填你的 API 域名（**必须 HTTPS 且已备案**）；一个月只能改 5 次，一次填好 |

| 用户隐私保护指引 | 设置 → 服务内容声明 → 用户隐私保护指引 | 逐项声明：**昵称、头像、手机号**（位置信息本期未采集） |

| 项 | 说明 |
| --- | --- |

## 三、服务器与运维

```bash
# 1. 部署
git clone <你的仓库> && cd server
cp .env.example .env && vim .env          # 填第一节的凭据 + 强随机 JWT_SECRET / ADMIN_TOKEN
npm install --production

# 2. 初始化数据库（幂等，可重复执行；会自动从 mock/menu.js 导入菜单）
NODE_ENV=production node src/db.js migrate
NODE_ENV=production node src/db.js seed

# 3. 用进程管理器托管（至少 2 副本）
pm2 start src/index.js -i 2 --name lbz-order
pm2 save && pm2 startup
```

### Nginx 参考配置

```nginx
server {
  listen 443 ssl http2;
  server_name api.你的域名.cn;
  ssl_certificate     /etc/ssl/fullchain.pem;
  ssl_certificate_key /etc/ssl/privkey.pem;

  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;  # 限流按真实 IP 计
    proxy_read_timeout 30s;
  }
  # 头像是本地上传时用；换对象存储后可删
  location /uploads/ { proxy_pass http://127.0.0.1:3000; expires 30d; }
}
```

### 上线前自检

```bash
curl -s https://你的域名/health          # {"status":"ok"}
curl -s https://你的域名/ready           # {"db":true,"redis":true,"degraded":false}
curl -s https://你的域名/metrics         # 观察 total / serverError
```

`NODE_ENV=production` 时服务启动前会强校验凭据完整性，**缺任何一项都会拒绝启动** —— 这是故意的。

## 四、上生产前建议调整的参数

| 参数 | 开发值 | 生产建议 |
| --- | --- | --- |
| `JWT_SECRET` | 默认占位串 | **必须换** 32 位以上随机串 |
| `ADMIN_TOKEN` | `dev-admin-token-...` | **必须换**，并只发给店长 |
| `DB_PASSWORD` | 本地密码 | 换成强密码，且不要用 root 账号 |
| `DB_CONN_LIMIT` | 20 | 按 `CPU 核数 × 2 + 磁盘数` 估，一般 20~50 |
| `MAX_INFLIGHT` | 2000 | 按单机承载能力调，宁小勿大（保护自己） |
| `ORDER_RATE_LIMIT` | 5 / 15 分钟 | 一般用户够用；团餐客户多可放宽到 10 |
| `MENU_CACHE_TTL` | 60s | 高峰期可调大到 120s 减轻 DB 压力 |
| 副本数 | 1 | ≥2，配合 Nginx 负载均衡 |

## 五、商家端使用

浏览器打开（手机也行）：

```
http://你的域名/admin?token=<ADMIN_TOKEN>
```

功能：接单 → 开始制作 → 出餐 → 完成（或拒单自动退款）、退款审核、库存管理、今日营业统计。
**看板每 10 秒自动刷新**，有催单会在卡片上标出。

> 生产环境务必走 HTTPS 并把 token 从 URL 里去掉（页面支持手动输入令牌并记住到 localStorage）。

## 六、上线后的观测

| 关注项 | 位置 | 阈值 |
| --- | --- | --- |
| 错误率 | `/metrics` 的 `serverError` | 目标 < 0.1% |
| 慢请求 | 日志里 `slow request` | 目标 < 1% |
| 支付成功率 | `mp_pay_record` 表按 status 统计 | 目标 ≥ 92% |
| 超时未支付 | `mp_order` 里 `status='UNPAID'` 且 `created_at` 超 15 分钟 | 应被自动清理 |
| 退款积压 | `/admin/refunds` 的 APPLIED 数量 | 及时处理 |
| 数据库 | 慢查询日志 + 连接数 | 连接数不应长期贴上限 |

**建议加一个定时任务**（cron / 定时器）：
1. 每 5 分钟扫一遍超时未支付的订单 → 关单 + 回滚库存 + 退券
2. 每 1 小时对「已支付但状态仍为 UNPAID」的订单调 `/orders/:id/query-pay` 做补偿对账
   （回调丢失时的兜底，接口已就绪）
