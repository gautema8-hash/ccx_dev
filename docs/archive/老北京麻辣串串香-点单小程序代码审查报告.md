## 2. 发现并已修复的问题（6 项）

### 🔴 P1 · 订单列表「进行中」角标恒为 0（`pages/orders/orders.js`）

**问题**：`counts` 依赖 `this.data.orders`，但它在 `setData` **生效之前**就被求值了 —— 读到的是上一轮的订单数组。

```js
// 修复前：this.buildCounts() 在构造 setData 入参时就执行了，此时 this.data.orders 还是旧值
this.setData({ orders, loading: false, counts: this.buildCounts() }, ...)

buildCounts() {
  return { ongoing: this.data.orders.filter(...).length }   // ← 旧数组
}
```

**影响**：首次进入永远是 0；后续每次进入显示的是"上一次"的数量，与列表内容不一致。

**修复**：把新数组显式传入。

```js
counts: this.buildCounts(orders),          // 用刚拿到的 orders
buildCounts(list) { ... (list || []) ... }
```

---

### 🟠 P2 · 购物车备注被刷新覆盖（`pages/cart/cart.js`）

**问题**：`refresh()` 里写的是 `remark: this.data.remark || state.remark`。用户把备注**清空**后，
只要再点一下数量加减触发 `refresh()`，`'' || state.remark` 会把旧文案又填回输入框。

**修复**：加 `_remarkTouched` 标记，用户动过输入框后以页面本地值为准；提交/失焦落库后复位。

```js
onRemarkInput(e) { this._remarkTouched = true; this.setData({ remark: e.detail.value }); }
// refresh 中
remark: this._remarkTouched ? this.data.remark : state.remark,
```

---

### 🟠 P2 · 隐藏的 tab 页仍在跟购物车 setData（`pages/menu/menu.js`、`pages/cart/cart.js`）

**问题**：`menu` 与 `cart` 都是 tab 页，**不会被 unload**，所以 `cart.subscribe` 的回调长期存活。
用户在「订单」页点"再来一单"时，隐藏着的点单页和购物车页也会各跑一次 `setData` —— 
每次 `setData` 都要跨 JS↔Native 线程序列化，这是纯浪费。

**修复**：用 `onShow/onHide` 维护可见性开关，隐藏时直接 return，回到页面时由 `onShow` 补一次。

```js
onShow() { this.visible = true;  this.refreshCart(); }
onHide() { this.visible = false; }
refreshCart() { if (!this.visible) return; ... }
```

---

### 🟠 P2 · 规格弹层反复加购可越过库存（`utils/cart.js`）

**问题**：列表里的步进器带 `max="{{dish.stock}}"`，但**带辣度的菜品走的是规格弹层**，
弹层每次把 `count` 重置为 1，用户可以反复点 `+` 打开弹层再确认，累计超过库存；`add()` 里只封顶到 99。

**修复**：`add()` 内统一按「库存与 99 取小」封顶，并让已存在的明细行也受同一上限约束。

```js
const cap = Math.min(99, Number(dish.stock) > 0 ? Number(dish.stock) : 99);
if (exist && exist.count >= cap) return key;   // 已达上限，幂等返回
```

> 真实环境下库存以服务端为准，这里只是客户端第一道闸。

---

### 🟠 P2 · 订单支付缺少幂等保护（`services/order.js`）

**问题**：`payOrder()` 对已支付订单没有任何判断。用户在订单列表和详情页快速连点，
或从两个入口同时发起，会把 `payTime` 覆盖成更晚的时间，导致订单状态机的时间基线漂移。

**修复**：加状态前置校验。

```js
if (cur === STATUS.CANCELED) return Promise.reject({ code: 'ORDER_CANCELED', message: '订单已取消，无法支付' });
if (cur !== STATUS.UNPAID)   return Promise.resolve(decorate(list[idx]));   // 幂等
```

---

### 🟡 P3 · `wx:for` 与 `wx:if` 写在同一元素（`pages/orders/orders.wxml`）

**问题**：订单卡的缩略图用 `wx:for="{{o.items}}"` + `wx:if="{{ii < 4}}"` 取前 4 个。
两者同元素时 `wx:for` 优先级更高、`wx:if` 按项逐个求值 —— 行为虽符合预期，但语义含糊、易被误改，
且白白渲染出所有菜品节点再丢弃。

**修复**：把"取前 4 个"挪到服务层，模板只做纯渲染。

```js
// services/order.js decorate()
thumbItems: items.slice(0, 4),

// orders.wxml
<view wx:for="{{o.thumbItems}}" wx:for-item="it" wx:key="key" class="order__thumb">{{it.emoji}}</view>
```

### 5.2 踩到的自动化坑（已固化进脚本，避免重复踩）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| **CSS 选择器穿不过自定义组件** | `page.$('.sku-panel')`、`page.$('stepper')` 一律返回 null | 组件内部一律改用 **XPath**（`//*[contains(@class,...)]` 可以穿透） |
| **`contains(@class,"sku-opt")` 会撞前缀** | 连带命中 `.sku-opts`（容器）和 `.sku-opt__dot`，下标全错位 | 用精确 class token：`contains(concat(" ",normalize-space(@class)," ")," sku-opt ")` |
| **`getElementsByXpath` 未实现** | 返回 undefined 导致 `elements.map` 崩溃 | 只用 `getElementByXpath`，靠下标谓词 `(//*[...])[n]` 取第 n 个 |
| **`page.callMethod` 不可用** | 报 `this.resetLocal is not a function` | 需要触发页面方法时，改为点真实控件 |
| **清 Storage 清不掉购物车** | `wx.removeStorageSync('lbz_cart_v1')` 后件数依旧是旧值 | `utils/cart.js` 的 `state` 是**模块级内存缓存**，必须走 UI 的「我的 → 清除本地缓存」（内部调 `cart.clearAll()`） |
| **`mini.evaluate` 改 Storage 对订单有效、对购物车无效** | 订单每次 `readAll()` 都读 Storage，购物车读内存 | 订单可直接改 Storage；购物车必须走 UI |
| **组件内元素 `offset()` 可能返回 `0,0`** | `tap()` 落点错误导致点击无反应 | 见 5.3 限制说明 |
| **`automator.launch` 在 Windows 上起不来** | `Failed to launch wechat web devTools` | 改成两步：先 `cli.bat auto --project <路径> --auto-port 9420`，再 `automator.connect({wsEndpoint})` |
| **`touristappid` 被自动化层直接拒绝** | 日志 `formatProject reject tourist/empty appid` | `project.config.json` 必须填真实 AppID |

### 5.3 已知覆盖不到的一处（非缺陷）

原因：它位于 `#ctl-* > <stepper>` 这层嵌套自定义组件里，DevTools 自动化对该元素的
