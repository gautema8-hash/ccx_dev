## 2. 测试策略

| 原则 | 说明 |
| --- | --- |
| 断言"最坏情况" | 越权时兜底必须是「查不到」而非「泄露」；并发时必须是「不多卖一份」而非"大致够" |
| 黑盒 HTTP 断言 | 不依赖任何测试框架，`node test/xxx.test.js` 直接跑，无额外供应链 |
| 套件自给自足 | 每个套件自己铺数据夹具（如库存），消除套件间隐式顺序依赖 |
| 可重复执行 | 连锁套件会复位主题状态、复用/复位测试账号，连续执行结果一致 |
| 失败信息带上下文 | 断言失败时打印服务端 `code` 与 `message`，不做"黑盒猜谜" |
| 不为测试削弱安全策略 | 管理端登录有 IP 限流，测试用令牌缓存规避，而不是调高阈值 |

## 5. 复现方式

```bash
# ---- 后端：340 项 ----
cd server
node src/db.js migrate && node src/db.js seed
node src/index.js            # 另开终端
npm test                     # api 113 → chain 160 → concurrency 26 → resilience 47
npm run test:chain           # 只跑连锁能力

# ---- 小程序 ----
node tools/audit-miniprogram.js                 # 静态审查（0 error）
node tools/build-preview.js                     # 重建预览
node tools/verify-preview.js                    # 41 项

# ---- 模拟器端到端（需开发者工具服务端口已开启）----

```

### 环境约束

| 约束 | 说明 |
| --- | --- |
| 管理端登录 IP 限流 | 40 次 / 5 分钟。连续多轮跑全套可能触发（`42900`）；测试用 `server/test/.token-cache.json` 缓存令牌规避；手工重跑可等待 5 分钟或清理 `lbz:r:stafflogin:ip:*` |
| 库存为共享状态 | 并发测试会卖空它操作的菜品；各套件已自铺夹具，属预期 |
| 服务必须已启动 | 所有后端测试为黑盒 HTTP，依赖 `http://127.0.0.1:3000` |
