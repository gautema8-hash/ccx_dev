## 3. 安装部署流程

### 3.1 本地 / 联调环境（最快路径）

```bash
# 1. 后端
cd server
npm install
cp .env.example .env          # 按需改 DB / Redis（默认 mock 登录与 mock 支付）
node src/db.js migrate
node src/db.js seed
node src/index.js             # http://127.0.0.1:3000

# 2. 自检
curl http://127.0.0.1:3000/ready
# {"code":0,"data":{"db":true,"redis":true,"degraded":false}}

# 3. 小程序
#    用微信开发者工具打开 lbz-chuanchuan/
#    utils/config.js 中 USE_MOCK=false、BASE_URL 指向 http://127.0.0.1:3000/miniapp/v1
#    （真机调试需勾选「不校验合法域名」或配置内网穿透 + HTTPS）

# 4. 管理后台
#    浏览器打开 http://127.0.0.1:3000/admin
```

### 3.2 生产环境

见《04-运维文档》第 3 节（单节点 / 多节点集群）。

关键前置：

| # | 项 |
| --- | --- |
| 1 | `NODE_ENV=production`（触发配置强校验，缺项拒绝启动） |
| 2 | `JWT_SECRET` 换成 ≥32 位随机串 |
| 3 | 微信登录/支付改 `real` 并配齐凭据 |
| 4 | 演示账号改密；生产另行建号并最小化门店授权 |
| 5 | 全站 HTTPS |
| 6 | 多节点时上传目录改对象存储、Redis 共享、代理带 `X-Forwarded-For` |

### 3.3 数据初始化

`node src/db.js seed` 会写入：

| 数据 | 数量 |
| --- | --- |
| 品牌 | 1（`brand_lbz`） |
| 门店 | 5（3 直营 + 2 加盟，含北京坐标） |
| 菜品 | 30 款 × 5 门店 = 150 条门店库存覆盖 |
| 员工账号 | 6（覆盖 5 种角色） |
| 主题 | 4（品牌级 3 + 东直门店门店级 1） |
| 优惠券模板 | 5（现金/锅底/折扣，含门店限定券） |

菜单数据**直接复用小程序的 `mock/menu.js`**，前后端菜单天然一致，改一处即可。

## 4. 验收标准

### 4.1 功能验收

| # | 验收项 | 判定方式 | 结果 |
| --- | --- | --- | --- |
| A-01 | 顾客可定位并看到按距离排序的门店 | `GET /stores?lat=&lng=` 返回按距离升序 | ✅ |
| A-02 | 未授权定位时仍可用 | 无坐标返回列表 + `needLocation=true` | ✅ |
| A-03 | 门店菜单与库存按门店隔离 | 加盟店停售菜品只在该店不可见 | ✅ |
| A-04 | 下单与支付闭环 | 下单 → 支付 → 状态推进 → 完成发积分 | ✅ |
| A-05 | 订单状态机不可跳步 | 跳步返回 `40901` | ✅ |
| A-06 | 已支付订单不能直接取消 | 返回 `40001`，必须走退款 | ✅ |
| A-07 | 优惠券可领、可用、抵扣正确 | 三种券型抵扣与服务端口径一致 | ✅ |
| A-08 | 团购券可核销且不可重复 | 并发 10 次只成功 1 次 | ✅ |
| A-09 | 主题可配置并即时生效 | 一键切换后小程序配色变化 | ✅ |
| A-10 | 加盟商只能看到自己门店的数据 | 列表为空或仅含本店 | ✅ |
| A-11 | 低权限角色不能提权 | 区域经理建超管被拒 | ✅ |
| A-12 | 管理端写操作留痕 | `mp_audit_log` 有记录 | ✅ |

### 4.2 非功能验收

| # | 指标 | 目标 | 实测 | 结果 |
| --- | --- | --- | --- | --- |
| B-01 | 接口 P95 | ≤ 500 ms | 168 ms | ✅ |
| B-02 | 接口 P99 | ≤ 800 ms | 183 ms | ✅ |
| B-03 | 混合负载 5xx | 0 | 0 / 120 | ✅ |
| B-04 | 防超卖 | 不多卖一份 | 库存 20 / 并发 60 → 成功 20 | ✅ |
| B-05 | 幂等 | 同 key 只产生一笔 | 并发 5 → 1 笔 | ✅ |
| B-06 | Redis 故障 | 服务不中断 | 9 项降级场景全绿 | ✅ |
| B-07 | 优雅关闭 | 发布不中断 | 端口释放、在途完成 | ✅ |
| B-08 | 注入/穿越/XSS | 不产生安全事件 | 47 项健壮性用例全绿 | ✅ |
| B-09 | 越权 | 全部拒绝 | 8+ 类越权场景 403 | ✅ |
| B-10 | 小程序静态审查 | 0 error | 0 error / 7 提示 | ✅ |

### 4.3 验收执行方式

```bash
# 后端（340 项）
cd server && npm test

# 小程序静态审查
node tools/audit-miniprogram.js

# 预览版回归（41 项）
node tools/build-preview.js && node tools/verify-preview.js

# 模拟器端到端（82 项，需开发者工具服务端口已开启）
node tools/e2e-automator.js
```

**验收判定**：上述全部通过，且 `docs/08` 中的「遗留风险清单」无未闭环的 P0/P1 项。

### 4.4 人工验收路径（管理后台）

| 步骤 | 预期 |
| --- | --- |
| 用 `owner_ft` 登录 | 门店列表仅 1 家；侧边栏无「员工管理」「审计」 |
| 用 `admin` 登录 → 主题管理 → 一键套用「会员日」 | 小程序刷新后变黑金配色 |
| 用 `mgr_dz` 登录 → 团购券核销 → 输入 `MT16800000001` | 返回「招牌串串双人餐 ¥168」 |
| 再用同一券码核销一次 | 提示已核销，并带出原始核销时间与门店 |
| 用 `admin` → 优惠券 → 定向发放给某用户 | 该用户「我的券」立即可见 |

## 5. 交付边界与假设

| # | 说明 |
| --- | --- |
| 1 | 支付与美团核销默认为 **mock 模式**，可在无凭据环境跑通全链路；真实接入需配齐凭据（属配置变更，不改代码）。 |
| 2 | 小程序当前使用**测试号 AppID**，真机预览与提审需换正式号。 |
| 3 | 上传文件默认落在本地 `uploads/`，**多节点部署必须改对象存储**。 |
| 4 | 种子数据中的 6 个员工账号密码为演示值，**生产必须改密**。 |
| 5 | 未包含配送/外卖、会员储值、供应链等能力（见《01-需求文档》第 2.3 节）。 |
| 6 | 容量与 SLA 相关指标需业务侧确认（见各文档 TODO 项）。 |
