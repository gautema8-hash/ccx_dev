## 1. 产品定位与目标

为连锁餐饮品牌提供「顾客点单 → 门店接单 → 总部运营」闭环能力：

- **顾客端（小程序）**：就近选店、浏览菜单、选串加购、选口味辣度、购物车调整、优惠券、团购券核销、下单支付、订单状态跟踪、评价。
- **运营端（管理后台）**：多门店管理、菜单与库存、订单流转、优惠券运营、主题换肤、团购券核销与对账、员工与权限、审计日志。

### 3.4 数据隔离规则

| 规则 | 说明 |
| --- | --- |
| 隔离发生在 SQL 层 | 所有列表查询必须走 `rbac.applyScope()`，产出 `AND store_id IN (...)`；**禁止业务代码自行拼门店条件** |
| 兜底方向 | 无授权门店时返回 `AND 1=0`（查不到），**不报错、更不返回全量** |
| 越权断言 | 针对指定门店的写操作必须先 `assertStore()` |
| 权限即时生效 | 令牌只做身份证明；每次请求重新查库解析门店范围，改权限后旧令牌立即失效 |
| 防提权 | 只有品牌超管能创建/修改品牌超管账号 |
| 发券范围 | 有 `coupon:write` 也不得把券限定到授权范围外的门店（独立校验） |

## 4. 核心业务流程

### 4.1 顾客下单主流程

```
进入小程序
  └─ 静默登录（wx.login → code2session → JWT）
  └─ 读取本地缓存门店 → 加载主题
  └─ 定位（可拒绝）→ 附近门店列表（按距离排序）
选门店 → 加载该店菜单（含门店价/库存）→ 校正购物车
  └─ 浏览/搜索 → 选规格 → 加购
  └─ 购物车：锅底/蘸料/就餐方式/桌号/备注
  └─ 结算页：选优惠券（服务端算可用性与抵扣）
  └─ 提交订单（幂等键）
       └─ 服务端：校验在售 → 原子扣库存 → 服务端计价 → 核销券 → 落库
  └─ 支付（微信支付 v3 / mock 收银台）
  └─ 订单详情（时间轴、取餐码）
```

### 4.2 订单状态机

```
UNPAID ──支付──▶ PAID ──接单──▶ ACCEPTED ──制作──▶ COOKING
   │                                                  │
   │用户取消                                       出餐就绪
   ▼                                                  ▼
CANCELED ◀──拒单/退款── PAID/ACCEPTED            READY ──完成──▶ DONE
```

| 流转 | 触发方 | 约束 |
| --- | --- | --- |
| `UNPAID → PAID` | 支付回调 | 验签 + 金额比对后才改单 |
| `PAID → ACCEPTED` | 门店接单 | 权限 `order:advance` |
| `ACCEPTED → COOKING → READY → DONE` | 门店推进 | 白名单，跳步拒绝 |
| `→ CANCELED` | 用户（仅 UNPAID）/ 门店拒单 / 退款通过 | 已支付必须走退款，不允许直接取消 |
| 完成 | — | 发放积分（实付元数） |

### 4.3 团购券核销流程

```
输入券码 → 规范化（去空格/连字符、转大写）
  → ① 本地查重（uk: platform+code）
  → ② 平台校验（mock 规则 / 美团开放平台）
  → ③ 面值上限保护
  → ④ 落库（唯一键兜底并发）
  → 返回套餐名/面值/门店/时间
```

两条通道（店员代客 `STAFF` / 顾客自助 `SELF`）**共用同一份核销逻辑**，避免"自助通道没有防重"的缺口。

### 4.4 优惠券流程

```
发券：新客自动 / 领券中心自领 / 活动 / 管理端定向发放
  └─ 三重约束：总量、每人限领、每日限领（条件更新，防超发）
用券：结算页 → POST /coupons/usable → 服务端算「能不能用 + 省多少」
  └─ 下单时再次核算，抵扣不超过订单金额
```

### 4.5 主题生效流程

```
运营端配置主题（品牌级或门店级）+ 时间窗 + 优先级
  → 小程序请求 GET /theme?storeId=
  → 解析：门店级 > 品牌级 > 默认令牌（差异式合并）
  → 下发 tokens + style 串
  → 页面根节点 style="{{themeStyle}}" → CSS 变量向下继承
```

## 5. 非功能性需求

### 5.1 性能

| 指标 | 目标 | 实测 | 来源 |
| --- | --- | --- | --- |
| 接口 P95 延迟 | ≤ 500 ms | **168 ms**（120 并发混合负载） | `test/concurrency.test.js` |
| 接口 P99 延迟 | ≤ 800 ms | **183 ms** | 同上 |
| 5xx 比例 | 0 | **0 / 120** | 同上 |
| 菜单缓存 | 60 s，按门店维度 | 命中缓存不查库 | `config.biz.menuCacheTtl` |
| 小程序主包 | 越小越好 | 零图片资源（emoji + CSS 渐变），`lazyCodeLoading: requiredComponents` | `app.json` |
| 并发承载 | TODO（需业务侧给出峰值 QPS 与门店数） | 单机 120 并发无错 | — |

> 已实现的性能手段：Redis 缓存（菜单/限流/锁/幂等）、按门店缓存隔离、请求并发去重、幂等请求指数退避重试、单请求 15 s 超时、连接池上限与排队上限、过载保护 `MAX_INFLIGHT`。

### 5.2 安全

| 项 | 要求 | 实现 |
| --- | --- | --- |
| 口令存储 | 不可逆 + 每账号独立盐 | `scrypt`（keylen 64）+ 16 字节随机盐 |
| 口令比对 | 抗时序侧信道 | `crypto.timingSafeEqual` |
| 暴力破解 | 有限次 + 锁定 | IP 40 次/5 分钟；账号连续失败 5 次锁 15 分钟 |
| 账号枚举 | 不可区分 | 账号不存在与密码错误返回同一文案 |
| 弱口令 | 拒绝 | ≥8 位、字母+数字、禁 `123456/password/admin` 开头 |
| 首登 | 强制改密 | `must_change_pwd=1` 时只放行改密/登出/个人信息 |
| 令牌 | 短时效 + 可吊销 | 访问 2 h、刷新 7 d、轮换、jti 黑名单 |
| 越权 | 双重断言 | 权限点 + 门店范围（范围校验独立于权限点） |
| 注入 | 参数化 | 全量 `?` 占位；动态片段仅白名单字段 |
| XSS | 转义 + 白名单 | 后台模板全量 `esc()`；头像只接受 `https://` 或站内路径；主题令牌字符白名单 |
| 上传 | 内容校验 | 魔数校验仅 JPG/PNG；响应头 `nosniff` + CSP `sandbox` |
| 路径穿越 | 阻断 | 解码后校验 `..` `\` 与绝对路径，并 `path.resolve` 二次确认 |
| 传输 | HTTPS | 生产 `HSTS`；request 合法域名由小程序平台强制 |
| 重放 | 时间窗 | 支付回调 5 分钟时间戳窗口 + 验签 |
| 日志 | 脱敏 | 密钥类置 `***`；手机号/openid/券码部分掩码 |
| 审计 | 全量留痕 | 管理端所有写操作进 `mp_audit_log`；登录进 `mp_login_log` |
| 防逆向 | 服务端裁决 | 价格/优惠/库存/状态一律服务端重算，客户端传值丢弃 |

### 5.3 可用性

| 项 | 要求 | 实现 |
| --- | --- | --- |
| 服务可用性目标 | TODO（需业务侧确认 SLA，如 99.9%） | 多节点 + 负载均衡方案见《04-运维文档》 |
| Redis 故障 | 服务不中断 | 整体降级：缓存穿透 DB、限流与锁退化进程内、幂等靠 DB 唯一键 |

| 异常 | 不崩进程 | handler 全 try/catch + `unhandledRejection` 兜底 |
| 数据 | 可恢复 | 备份策略见《04-运维文档》 |

## 6. 业务规则清单

| 编号 | 规则 |
| --- | --- |
| BR-01 | 金额一律以「分」为整数运算与存储，仅展示层转元 |
| BR-02 | 菜品价格以服务端库内价为准；门店可通过 `price_override` 改价，`0` 表示沿用总部价 |
| BR-03 | 门店停售只影响该门店，不影响品牌菜单与其他门店 |
| BR-04 | 打包费仅自取收取，金额由服务端下发（`config.biz.packFee`） |
| BR-05 | 锅底为订单级必选项；蘸料多选免费 |
| BR-06 | 堂食必须选桌号，自取不需要 |
| BR-07 | 单笔订单金额上限 `MAX_ORDER_AMOUNT`（默认 ¥1000） |
| BR-08 | 单用户 15 分钟内最多下单 `ORDER_RATE_LIMIT`（默认 5）笔 |
| BR-09 | 已支付订单不允许直接取消，必须走退款 |
| BR-10 | 完成订单发放积分 = 实付元数 |
| BR-11 | 一单只能评价一次 |
| BR-12 | 取餐号按「门店 + 日期」独立循环，避免多店串号 |
| BR-13 | 优惠券抵扣不超过订单金额，不出现负数实付 |
| BR-14 | 团购券一经核销即占用券码；撤销核销不释放券码（防重复利用） |
| BR-15 | 团购券核销需门店处于营业时间内（支持「次日 02:00」跨天营业时间） |
| BR-16 | 默认门店按「直营优先 + 门店编码升序」（即 BJ001 东直门总店） |
