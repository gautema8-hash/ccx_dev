# 老北京麻辣串串香 · 连锁点单系统
# 运维手册

> 覆盖：部署步骤（单节点 / 多节点集群）、配置项、监控告警、日志、备份策略、常见故障处理。
> 配套配置文件：`deploy/nginx-single.conf`、`deploy/nginx-cluster.conf`、`deploy/lbz-order.service`、`deploy/pm2.config.cjs`。

## 1. 环境依赖

| 组件 | 版本要求 | 用途 | 是否必须 |
| --- | --- | --- | --- |
| Node.js | ≥ 18 | 应用运行时 | 必须 |
| MySQL | 8.x | 主存储（27 张表） | 必须 |
| Redis | 5.x+ | 缓存 / 限流 / 分布式锁 / 幂等 / 令牌黑名单 | 建议（**可降级**） |
| Nginx | 1.18+ | TLS 终止 / 负载均衡 / 入口限流 | 生产必须 |
| 对象存储 | — | 上传文件（头像、票据） | **多节点必须**；单节点可选 |
| PM2 或 systemd | — | 进程守护 | 二选一 |

**端口**：

| 端口 | 用途 |
| --- | --- |
| 3000 | 应用 HTTP（`PORT` 可配） |
| 443 / 80 | Nginx 对外 |
| 3306 / 6379 | MySQL / Redis（内网，不对外） |

## 2. 配置项说明

配置文件：`server/.env`（从 `server/.env.example` 复制）。环境变量优先级高于文件。

### 2.1 服务

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `NODE_ENV` | `development` | 设为 `production` **会触发启动强校验**，缺关键配置直接拒绝启动 |
| `PORT` | `3000` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `API_PREFIX` | `/miniapp/v1` | 接口前缀，需与小程序 `utils/config.js` 的 `BASE_URL` 对应 |
| `MAX_INFLIGHT` | `2000` | 过载保护阈值，超过直接 503（拒绝而非排队，防雪崩） |
| `BODY_LIMIT` | `262144` | 请求体上限（字节），超限 413 |

### 2.2 令牌

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `JWT_SECRET` | 开发默认值 | **[生产必改]** ≥32 位随机串；仍是默认值时生产环境拒绝启动 |
| `JWT_TTL` | `604800` | 用户访问令牌（秒，7 天） |
| `REFRESH_TTL` | `2592000` | 用户刷新令牌（秒，30 天） |
| `STAFF_TOKEN_TTL` | `7200` | 员工访问令牌（秒，2 小时） |
| `STAFF_REFRESH_TTL` | `604800` | 员工刷新令牌（秒，7 天） |

### 2.3 数据库与缓存

| 键 | 默认 | 说明 |

## 3. 部署步骤

### 3.0 通用前置

```bash
# 1) 拉取代码并安装依赖（只有 2 个直接依赖）
cd server
npm ci --omit=dev

# 2) 生成配置
cp .env.example .env
#    按第 2 节填写：DB_*、REDIS_*、JWT_SECRET、NODE_ENV=production …

# 3) 建表 + 初始化种子数据（幂等，可重复执行）
node src/db.js migrate
node src/db.js seed

# 4) 自检：生产配置校验由启动流程自动执行，缺项会拒绝启动
node src/index.js
```

启动后自检：

```bash
curl http://127.0.0.1:3000/ready
# {"code":0,"data":{"db":true,"redis":true,"degraded":false}}
```

### 3.1 模式 A：单节点部署

```
用户 → Nginx(443) → Node(3000) → MySQL / Redis
```

```bash
# 1) 安装 Nginx 配置
sudo cp deploy/nginx-single.conf /etc/nginx/conf.d/lbz.conf
#    修改 server_name 与证书路径（TODO）
sudo nginx -t && sudo systemctl reload nginx

# 2) 托管进程
sudo useradd -r -s /sbin/nologin lbz
sudo mkdir -p /opt/lbz-order && sudo cp -r . /opt/lbz-order/
sudo chown -R lbz:lbz /opt/lbz-order
sudo cp deploy/lbz-order.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now lbz-order

# 3) 验证
curl -k https://your-domain/ready
```

适用：试点、单店、低流量阶段。`TODO`：明确切换到集群模式的触发阈值（建议以峰值 QPS 或日订单量为依据）。

### 3.2 模式 B：多节点集群部署（面向全国用户）

```
用户 → DNS → LB(Nginx/CLB) → [Node × N] → 共享 Redis + MySQL 主从 + 对象存储
```

**前置检查清单（逐项确认，缺一会导致隐蔽故障）**：

| # | 检查项 | 不满足的后果 |
| --- | --- | --- |
| 1 | 所有实例使用**同一个** `JWT_SECRET` | 令牌在部分实例校验失败，随机掉登录 |
| 2 | 所有实例连**同一个** Redis | 限流/锁/幂等计数不一致，可能出现超卖或重复扣款 |
| 3 | 上传目录已改对象存储或共享存储 | 头像/票据在部分实例 404 |
| 4 | 反向代理带 `X-Forwarded-For` | 全国用户被算成同一个 IP，限流误伤全站 |
| 5 | 数据库账号在所有节点可连通 | 节点启动失败或间歇性 500 |

**步骤**：

```bash
# 1) 每台应用节点：同 3.0 通用前置 + 安装 systemd 单元
sudo cp deploy/lbz-order.service /etc/systemd/system/
sudo systemctl enable --now lbz-order

# 2) 负载均衡节点：安装集群 Nginx 配置，填入各实例地址
sudo cp deploy/nginx-cluster.conf /etc/nginx/conf.d/lbz.conf
#    编辑 upstream 块，把 10.0.1.11/12/13 换成真实内网 IP
sudo nginx -t && sudo systemctl reload nginx

# 3) 上传目录迁移对象存储（TODO：按所选云厂商配置）
#    迁移后把 /uploads/ 的 location 改为 CDN/对象存储回源

# 4) 验证：连续请求确认命中不同实例且行为一致
for i in $(seq 1 10); do curl -s https://your-domain/health | head -c 60; echo; done
```

**水平扩展**：

```bash
# 新增一台应用节点 → 装好服务 → 在 Nginx upstream 加一行
server 10.0.1.14:3000 max_fails=3 fail_timeout=10s;
sudo nginx -t && sudo systemctl reload nginx    # reload 不断连接
```

**缩容**：先在 upstream 注释掉该节点并 reload（新流量不再进入），等其处理完在途请求后再停机。

**滚动发布（零中断）**：

```bash
# 逐台执行：应用收到 SIGTERM 后停止接新请求 → 等在途完成 → 退出
sudo systemctl restart lbz-order
# LB 通过 /ready 探测：DB 不可用时该节点返回 503，自动摘除
```

### 3.3 单机多实例（PM2，可选）

不想引入多机编排时，可在单机起多实例利用多核：

```bash
npm i -g pm2
pm2 start deploy/pm2.config.cjs --env production
pm2 save && pm2 startup
```

> 注意：PM2 cluster 只解决单机多核；**跨机高可用仍需 Nginx upstream**。

## 4. 会话、缓存与数据一致性（多节点专项）

| 关注点 | 机制 | 运维要点 |
| --- | --- | --- |
| 会话共享 | 无服务端 Session：用户端 JWT 任意实例可验；员工端 jti 黑名单存 **Redis** | Redis 必须共享，否则"登出不生效" |
| 缓存共享 | 菜单缓存、限流、幂等、分布式锁全部走 Redis | Redis 必须共享且**持久化** |
| 库存一致性 | `UPDATE ... WHERE stock >= ?` 原子语句 + 事务，跨实例同样安全 | 无需额外处理 |
| 单号唯一 | `mp_seq` 事务内 `SELECT ... FOR UPDATE` 行锁 | 依赖数据库行锁，跨实例安全 |
| 券防重 | DB 唯一键 `uk(platform, code)`，**不依赖缓存** | 无需额外处理 |
| 券防超发 | `UPDATE ... WHERE issued < total` 条件更新 | 无需额外处理 |
| 缓存失效 | 写操作主动失效 + 60 s TTL 兜底 | 运营改价后最多 60 s 生效延迟 |
| 文件上传 | **本地磁盘在集群下不可共享** | 必须改对象存储 |

## 5. 监控告警

### 5.1 内置探针与指标

| 端点 | 用途 | 告警建议 |
| --- | --- | --- |
| `GET /health` | 存活探针（进程在即 200） | 连续 3 次失败 → 紧急 |
| `GET /ready` | 就绪探针（DB 不可用返回 503，Redis 不可用标记 `degraded`） | 503 持续 → 摘除节点并告警 |
| `GET /metrics` | 指标：`total` `ok` `bizError` `serverError` `rejected` `slow` `inflight` `uptime` | 见下表 |

### 5.2 建议告警规则

| 指标 | 阈值 | 级别 | 处理 |
| --- | --- | --- | --- |
| `serverError`（5xx） | 5 分钟内 > 0 | 紧急 | 查日志 `requestId`，定位异常栈 |
| `rejected`（过载拒绝） | 5 分钟内 > 0 | 重要 | 扩容或调高 `MAX_INFLIGHT`（先确认机器能力） |
| `slow`（慢请求） | 占比 > 5% | 重要 | 查慢 SQL 与 Redis 延迟 |
| P95 延迟 | > 500 ms | 重要 | 查 DB 连接池、Redis、慢 SQL |
| `inflight` | 持续接近 `MAX_INFLIGHT` | 重要 | 扩容 |
| `/ready` 返回 503 | 任意 | 紧急 | DB 连通性 |
| Redis `degraded: true` | 持续 > 5 分钟 | 重要 | 恢复 Redis；期间限流与锁退化为单机语义（见 R-03） |
| 库存为负 | 任意 | 紧急 | 立即止损并排查（正常情况不可能为负） |
| 券 `issued > total` | 任意 | 紧急 | 超发，立即下架该券 |
| 支付回调失败 | 连续 > 3 | 紧急 | 查证书/签名/网络 |

## 6. 日志

### 6.1 应用日志

| 项 | 说明 |
| --- | --- |
| 格式 | JSON Lines（一行一条，便于采集） |
| 输出 | 标准输出 / 标准错误（由 systemd 或 PM2 落盘） |
| 目录 | `server/logs/`（`stdout.log` / `stderr.log` / `pm2-*.log`） |
| 级别 | 生产 `info` 及以上；开发含 `debug` |
| 字段 | `t` 时间、`lv` 级别、`msg`、`pid`、`requestId`、`path`、`status`、`cost`、`ip`、`uid` 等 |

**脱敏规则**（`src/logger.js`）：

| 字段 | 处理 |
| --- | --- |
| `token` `access_token` `refresh_token` `authorization` `password` `session_key` `secret` `appSecret` `apiv3Key` `privateKey` | 置 `***` |
| `openid` | 保留前 6 位 |
| `phone` `mobile` `tel` | `138***1234` |
| `idCard` `idNo` | `110101****1234` |
| `code`（券码 / 微信登录 code，长度 ≥ 8） | 保留前 4 位 |

### 6.2 排障用法

```bash
# 按 requestId 串联一次请求的全过程
grep '"requestId":"mv86ltq7-uic-1"' server/logs/stdout.log

# 看 5xx
grep '"lv":"error"' server/logs/stderr.log | tail -50

# 看慢请求
grep '"slow":true' server/logs/stdout.log | tail -20
```

## 8. 常见故障处理

| 现象 | 可能原因 | 排查 | 处理 |
| --- | --- | --- | --- |
| 服务起不来，提示配置缺失 | 生产强校验命中 | 看启动日志的具体条目 | 补齐 `JWT_SECRET` / 支付凭据 / AppSecret 等 |
| 启动报 `EADDRINUSE` | 端口被占用 | `netstat -ano \| grep :3000` | 停掉旧进程或改 `PORT` |
| `/ready` 返回 503 | MySQL 不可达 | 检查 DB 主机、账号、连接池是否打满 | 恢复 DB；必要时扩容 `DB_CONN_LIMIT` |
| `/ready` 标记 `degraded` | Redis 不可达 | 检查 Redis 主机、密码 | 恢复 Redis；期间服务可用但限流/锁退化为单机语义 |
| 大量 503 `rejected` | 触发过载保护 | `/metrics` 的 `inflight` | 扩容实例或调高 `MAX_INFLIGHT` |
| 下单报「库存不足」但后台显示有货 | 缓存未失效 / 门店维度弄错 | 确认查的是**同一门店**的 `storeStock` | 改库存后缓存会自动失效，最多等 60 s |
| 用户反馈"页面显示 ¥20、实付 ¥22" | 价格/打包费双源 | 确认小程序已用 `/menu` 下发的 `packFee` 与门店价 | 见《07-代码审查报告》已修复项 |
| 优惠券"列表可用、下单不可用" | 抵扣口径不一致 | 结算页是否已改用 `POST /coupons/usable` | 同上 |
| 团购券重复核销 | 唯一键被绕过？ | 查 `mp_voucher` 的 `uk(platform, code)` 是否存在 | 正常情况不可能；若发生立即止损 |
| 加盟商能看到别家门店数据 | 隔离失效 | 用该账号调 `/admin/stores` 复核 | 检查 `mp_staff_store` 授权与 `applyScope` 调用 |
| 管理后台一直转圈 | fetch 无超时（已修）/ 接口慢 | 浏览器 Network + 服务端 `/metrics` | 升级到含超时修复的版本 |
| 登录报"尝试过于频繁" | IP 限流（40 次/5 分钟） | 是否为 NAT 出口 IP | 等待或清理 `lbz:r:stafflogin:ip:*`；**不要随意调高阈值** |
| 头像 404（多节点） | 上传目录未共享 | 确认文件落在哪个实例 | 迁移对象存储 |
| 支付成功但订单未更新 | 回调未到达或验签失败 | 查 `mp_pay_record` 与日志 `pay notify` | 用 `POST /orders/:id/query-pay` 主动查单补偿 |
| 订单号重复 | `mp_seq` 异常 | 检查是否有人绕过 `nextSeq` | 修复后清理重复数据 |
| 小程序白屏 | 页面路径错误或菜单加载失败 | `onPageNotFound` 会兜底跳点单页 | 查 `/menu` 是否返回错误 |
